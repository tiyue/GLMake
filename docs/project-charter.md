- 部署只建立一个所有者账户，使用用户名、密码和一次性恢复码；不开放注册，不依赖邮件或
  第三方登录。密码和恢复码同时丢失时不承诺找回。
- 服务器保存完整 Markdown 正文、附件、笔记本、标签、必要搜索索引和有限版本历史。该实例

- 浏览器采用本地优先模型。首次登录由用户选择要上传的既有本地文档；登录后新建文档默认
  进入云同步。保留手动同步、每 10 分钟条件自动同步、离线续传和四路径冲突处理。
- 支持多个笔记本；每篇文档属于一个笔记本并可拥有多个标签。
- 分享仅提供可撤销的只读公开链接；第一版不提供指定用户权限或多人协作编辑。
- 普通删除进入回收站并保留 30 天，支持主动永久删除；每篇文档最多保留最近 10 个历史版本，
  历史版本最长保留 30 天，全实例历史版本空间上限为 5 GB。
- 单用户部署不需要公共注册、用户封禁、按用户配额或运营管理后台；仍须设置整套实例的磁盘
  水位、附件上限和请求限制，防止误操作耗尽服务器资源。
- 当前没有自动独立备份目标，改为提供可校验的“全量导出 + 全量导入/恢复”能力。产品负责人
  负责把导出包下载并保存在服务器之外；服务器故障时，最近一次导出之后且其他浏览器没有
  完整副本的数据可能永久丢失。自动异地备份作为以后可选增强，不是首版硬依赖。

## 3. 目标网站调研结论

### 3.1 产品定位

马克飞象不是普通内容展示网站。访问首页会直接进入 Markdown 编辑工作台。
官网将其定位为 Markdown 编辑器，核心价值由 Markdown 写作体验、浏览器本地保存和
跨设备同步共同构成。

### 3.2 已公开或实际观察到的能力

| 分类 | 当前网站表现 | 证据状态 |
| --- | --- | --- |

| Markdown | 标题、强调、链接、图片、列表、引用、代码、表格、复选框 | 官网帮助页 |

### 3.3 界面与交互观察

桌面宽屏状态：

- 工作区占据整个视口，主内容约为左右对半分栏。
- 编辑区使用深色背景，预览区使用浅色背景，形成明显的源码/结果分工。
- 常用操作以图标工具栏和左右侧边菜单承载，正文区域保持高信息密度。
- 文档菜单包含恢复、删除、导出、预览、分享；系统菜单包含设置和帮助。
- 页面使用大量图标字体，部分控件缺少清晰的可访问名称；不应无条件照搬。

窄屏状态：

- 实时预览被收起，编辑区成为主视图。
- 顶部只保留少量图标操作，正文采用单栏滚动。
- 这证明目标站有移动端降级逻辑，但不能证明其当前移动体验满足新项目要求。

异常与危险状态：

- 同一文档在另一窗口编辑时，当前窗口会进入只读模式并提示原因。
- 页面包含本地删除与“同时删除云端笔记”的不同危险级别。
- 页面公开内容包含本地/云端版本冲突、同步失败、图片上传失败、清空本地列表等状态。
- 这些状态属于产品规则，不只是视觉样式；若进入功能等价范围，必须单独定义和测试。

### 3.4 调研推断（不是已确认事实）

- 页面公开内容出现 StackEdit 的运行提示，说明马克飞象很可能在某个 StackEdit
  版本基础上进行了定制。
- 官网会员页可以证实产品存在付费同步限制；用户将其描述为闭源产品。本次未找到
  马克飞象官方公开源码仓库，但“未找到公开仓库”本身不能严格证明所有相关代码均未开源。
- 当前公开的 StackEdit 仓库是浏览器 Markdown 编辑器，并标注 Apache-2.0
  许可证。因此，“核对匹配版本后基于合法上游改造”可能比从零仿写更简单。
- 不能据此认定马克飞象的品牌、定制代码、图标、文案、服务端接口或其他资源也采用
  相同许可证；这些内容不得直接复制。
- 目标站真正昂贵的部分可能不是双栏界面，而是可靠本地存储、跨设备数据往返、
  冲突处理、附件上传、导出和多端一致性。

### 3.6 StackEdit 上游与马克飞象定制边界预研

- 马克飞象首页公开显示 Web 版本 `1.8.0`；其公开 `main_zh.js` bundle 内仍保留
  `constants.VERSION="4.3.0"`，结合目录、模块和 PageDown 结构，可确认其代码谱系来自
  StackEdit 4.3.0，而不是当前 StackEdit 5。
- 该证据只能证明“来源基线”，不能证明马克飞象等同于未经修改的 v4.3.0。`main_zh.js`、
  `marxico.css`、云端同步、中文文案和品牌资源均属于定制部分，尚未找到对应公开
  源码或许可证，因此不得复制。
- StackEdit v4.3.0 的公开仓库和许可证声明采用 Apache-2.0，可在遵守版权和许可证要求的
  前提下作为研究参考或候选上游。
- StackEdit 当前 master 的包版本为 5.15.4，最新标签为 v5.15.4，代码头提交日期为
  2023-05-27。它同样使用 Apache-2.0，但长期维护状态、旧依赖、安全风险以及与马克飞象
  4.3.0 行为差异仍需审计，不能因许可证兼容就直接确定为 GLMake 底座。

结论：马克飞象的上游谱系已定位，但定制代码边界不可从公开材料完整恢复。GLMake 可以
复用经许可证审计通过的 StackEdit 上游代码或现代独立库，不能复制马克飞象 bundle、CSS、
品牌素材或来源不明的定制实现。

### 3.7 浏览器本地持久化与离线能力预研

- IndexedDB 是面向复杂 Web 应用的事务型本地数据库，标准允许存储字符串、结构化对象、
  `Blob` 和 `File`；适合保存文档、索引、同步映射和附件。容量有限的 `localStorage`
  只适合少量偏好或迁移标记，不适合作为正文和附件主存储。
- Cache Storage 与 Service Worker 可以在安全上下文中缓存应用壳、脚本和样式，但公网 HTTP
  不保证能够注册 Service Worker，因此关闭页面后离线重开不属于当前 Must。
- 浏览器存储默认通常属于 best-effort。设备存储压力、Origin 配额、浏览器策略和用户
  主动清理都可能删除数据；超额写入会失败，应用必须捕获并向用户明确提示。
- 可以调用 `navigator.storage.estimate()` 监测估算用量，并通过 `persist()` 请求持久化；
  是否批准由浏览器决定，不能把请求成功写成产品保证。
- Safari/WebKit 对 IndexedDB、Cache、Service Worker 和 File System 统一实施配额与回收
  策略，因此 iOS Safari 必须单独进行容量、长期闲置、私密浏览和清理场景测试。

结论：仅浏览器本地保存的产品方向技术上可行，但无法承诺“浏览器永不丢数据”。正式需求
必须包含事务写入、写入后校验、配额监测、存储持久化请求、失败提示、定期导出提醒和可
验证的备份恢复；清除站点数据、私密浏览结束和用户未备份造成的丢失仍属于明确限制。

### 3.8 自有后端阶段 2 第一轮：数据底座与恢复链路

#### 3.8.1 本轮问题与通过门槛

本轮只回答以下问题：单用户、单台阿里云主服务器、浏览器本地优先的前提下，能否用足够少的
服务组件保存完整文档与附件，并建立可验证的同步和全量导出恢复链路？

公开资料调研的通过门槛：

- 数据库适合单主机低并发 Web 应用，支持事务、崩溃恢复、一致性快照和明确的升级路径。
- 正文、元数据、附件和搜索索引职责分开；索引损坏不得等于正文丢失。
- 多浏览器写入必须能检测旧版本提交，任何冲突均不得静默覆盖。
- 删除必须经过 30 天回收站和可同步的删除标记，不能只在某一浏览器消失。
- 全量导出包必须可校验、可以存放在服务器之外，并能在干净环境完成全量导入；必须明确
  没有自动异地备份时的数据丢失窗口。
- 所有方案必须可以写入公开部署文档，不依赖私有脚本或不可复现的人工秘方。

本轮没有进行运行时试验，因此不能据此宣称性能、崩溃恢复或备份恢复已经通过。

#### 3.8.2 候选数据底座

当前推荐的待验证候选是：**单体后端进程 + 单个 SQLite 数据库 + 主机文件系统中的
不可变附件对象 + 可重建全文索引 + 可移植全量导出/导入。** 这是预研候选，不是已经冻结的
技术设计。

选择依据与边界：

- SQLite 官方把低到中等流量网站和单应用本地存储列为适用场景。当前只有一个所有者账户，
  没有高并发、多主写入或横向扩容需求，尚无证据证明需要 PostgreSQL 等独立数据库服务。
- SQLite WAL 允许读写并行，但写入仍串行，且所有进程必须位于同一主机，不能把数据库文件
  放在网络文件系统上。该限制与当前单主机范围一致；若以后改为多服务器，必须重评数据库。
- SQLite Online Backup API 可以从正在使用的数据库生成一致性快照，避免直接复制活动数据库
  文件可能产生的不一致；`VACUUM INTO` 可作为另一种快照方式，但具体驱动支持仍需实测。
- Markdown 正文、标题、笔记本、标签、版本、删除标记、同步序号、分享记录和附件清单进入
  事务数据库。搜索索引属于可重建派生数据，不作为正文唯一副本。
- 大附件候选存入主机文件系统，数据库只记录内容哈希、大小、MIME、原始文件名和引用关系。
  SQLite 官方测试显示较大 BLOB 通常更适合独立文件；实际分界受硬件和文件系统影响，因此
  不在立项阶段硬编码 100 KiB 等阈值。第一候选统一把用户附件放到文件系统，减少数据库膨胀。
- 附件按内容哈希寻址，先写临时文件、校验长度和哈希、同步到磁盘，再原子改名为不可变对象，
  最后在数据库事务中建立引用。物理垃圾回收必须晚于回收站和版本保留期。
- SQLite FTS5 默认 `unicode61` 把连续字母或数字字符视为一个词元，对无空格中文不能直接
  假定满足全文搜索。FTS5 内置 trigram 子串索引是首个候选，但少于三个字符的查询存在限制；
  必须用中文、英文、数字、标点和混合文本固定样本验证。全文索引应可从正文完整重建。

暂不选择独立 PostgreSQL、搜索服务、MinIO 或消息队列：它们并非永远不使用，而是当前没有
与单用户规模相匹配的必要证据。若 SQLite 写锁、中文搜索、数据库大小、备份窗口或目标硬件
  一致性快照实测不达门槛，再重新比较替代方案。

#### 3.8.3 同步与冲突的最低协议

当前建议进入后续试验的协议模型：

- 每篇文档使用稳定、随机生成的文档 ID；本地副本和服务器副本共享同一 ID。
- 服务器维护单调递增的全局变更序号 `change_seq`，每个浏览器保存最后成功应用的检查点，
  只拉取检查点之后的变化。
- 每篇文档维护不可回退的 `revision`。浏览器写入必须携带自己编辑所依据的 `base_revision`；
  只有它等于服务器当前版本时才能直接生成下一版本。
- `base_revision` 落后时服务器不得覆盖，必须返回冲突；浏览器保留本地草稿和服务器版本，
  进入已确认的查看差异、使用本地版、使用云端版或另存两篇文档四条路径。
- 创建、更新、附件关联、移动笔记本、标签变化、进入回收站、恢复和永久删除都必须具有幂等
  请求标识，网络重试不得产生重复文档、重复版本或重复附件引用。
- 普通删除写入带时间的 tombstone 并同步到其他浏览器，30 天内允许恢复；达到期限后才能进入
  永久删除流程。附件物理回收还必须满足没有活动文档或保留版本引用。
- 当前不引入 CRDT 或实时协作算法。项目没有多人协作要求，已确认的显式冲突处理比自动合并
  更符合“不得静默丢失”的门槛；若以后要求同文档实时协作，必须重新立项。

以上是协议约束草案，尚未形成 API 或数据表设计。

#### 3.8.4 全量导出、导入与恢复候选链路

产品负责人已确认当前没有独立自动备份目标，改为增加“全部导出”以方便更换服务器。只提供
导出而没有导入与校验不能完成迁移目标，因此首版 Must 必须同时包含全量导入/恢复。

推荐进入后续需求定义和试验的最低链路：

1. 导出开始时暂停附件物理垃圾回收，使用 SQLite Online Backup API 生成一致性数据库快照，
   但不长时间阻塞正常编辑。
2. 生成版本化 GLMake 导出包，至少包含格式版本、应用版本、导出时间、文档、笔记本、标签、
   回收站、保留中的版本、附件及每个文件的大小和内容哈希。
3. 导出包不得包含密码哈希、恢复码哈希、会话、TLS 私钥或任何仍然有效的分享凭据。迁移后
   所有文档默认处于未分享状态，原分享链接全部失效，由所有者按需重新生成。
4. 产品负责人已确认导出包不加密。导出前必须明确提示：任何取得导出包的人都可以读取其中
   的全部正文和附件；应用不提供导出密码，也不得把未加密导出包宣传为安全备份介质。
5. 导出必须流式或分块生成，不能把约 500 MB 数据整体载入 2 GiB 内存。若使用服务器暂存
   文件，必须设置空间门槛、失败清理、过期清理和下载后清理；不承诺在 SSD 上完成物理安全擦除。
6. 全量导入先验证格式版本、总大小、文件数量、路径、内容哈希和剩余磁盘空间，禁止路径穿越、
   超额膨胀、重复对象覆盖和部分导入冒充成功。
7. 导入到全新服务器时先建立新的所有者凭据，再事务化导入业务数据；失败必须
   回滚到导入前状态。旧服务器的会话不得在新服务器继续有效。
8. 发布前必须在干净服务器上实际执行“导出 → 传输 → 导入 → 登录 → 搜索 → 打开文档与附件
   → 检查回收站和版本”的恢复演练，并核对哈希和数量；只有实际恢复成功才算迁移功能可用。

全量导出可以成为人工离线备份，但不会自动形成恢复点。产品负责人必须主动把导出包保存到
服务器之外；主服务器在两次导出之间发生不可恢复故障时，最近一次导出之后的数据可能丢失。
浏览器本地副本可能帮助恢复部分文档，但不作为完整备份承诺。restic/SFTP/对象存储仍可作为
以后可选的自动备份增强，本版本不以其为运行依赖。

#### 3.8.5 账户与会话基线

- 密码只保存单向哈希，不保存可解密密码。首选 Argon2id，参数必须在目标服务器上实测，且
  不低于 OWASP 当前建议的基线；不能用普通 SHA-256 直接哈希密码。
- 一次性恢复码也只保存哈希，使用后立即作废并生成新的恢复码；恢复流程必须使所有既有会话
  失效。密码和恢复码同时丢失时不提供绕过认证的后门。
- 登录成功后使用服务端会话和随机会话 ID；浏览器通过 `HttpOnly`、适当 `SameSite` 的 Cookie
  接收会话，不把会话令牌放入 URL 或 `localStorage`。公网 HTTP 下不能使用 `Secure` Cookie，
  产品负责人接受会话可能被截获的风险。
- 登录、恢复和分享管理接口仍需限速；退出、修改密码、使用恢复码和安全事件必须撤销相关会话。
- 会话最长有效期为 30 天；必须提供“退出所有设备”，并确保该操作立即撤销全部服务器会话。
- 当前目标服务器没有域名或 HTTPS，并已确认允许直接通过公网 HTTP 使用。所有者密码必须是
  仅供 GLMake 使用的独立密码，不得与邮箱、阿里云、GitHub 或其他账户复用。
- 公网 HTTP 不是安全上下文，Service Worker、异步剪贴板等浏览器能力可能受限。阶段 2 必须
  验证普通粘贴、图片粘贴、页面已打开时的离线编辑和关闭页面后的离线重开分别能否工作；
  不能把只能在 HTTPS 或 localhost 下工作的能力写成公网 HTTP 已支持。

#### 3.8.6 本轮结论

**资料层面可以继续，阶段 2 尚未通过。** SQLite、不可变附件文件、修订号同步和
可移植全量导出/导入组成的单服务器方案符合单用户范围，且比引入多项服务更简单；但以下事项没有
运行证据：目标服务器资源、SQLite 写入和中文搜索性能、附件中断恢复、数据库与附件一致性、
30 天删除和版本回收、导出下载以及干净环境导入恢复。

目标服务器规格、附件规模和 100—1000 篇文档规模已经补充。进入技术试验后只能使用合成文档与附件，
不能使用真实私密笔记；试验产物不得冒充正式功能。

### 3.9 目标服务器、数据规模与全量迁移约束

产品负责人通过阿里云控制台截图提供了目标环境。本文只记录架构与容量需要的信息，不记录
截图中的公网 IP、实例标识、内网地址、到期时间或瞬时监控值。

#### 3.9.1 已确认环境与规模

#### 3.9.2 初步容量判断

- 40 GiB 系统盘相对于 500 MB 活动附件上限有明显名义余量，但系统、现有服务、日志、数据库
  版本、回收站、搜索索引和临时导出都会占用同一块盘。截图没有显示实际可用空间，因此目前
  只能判断“候选可行”，不能宣布容量通过。
- 500 MB 必须按物理存储水位解释：活动文档、回收站、保留版本和去重后的附件对象共同占用
  空间。产品层的活动附件额度不能阻止部署层设置更高一级的磁盘警戒线和写入熔断。
- 附件使用内容哈希去重时，相同二进制只保存一份；不同版本引用同一附件不重复占用 50 MB。
  只有引用全部过期且经过导出/恢复保留规则后，物理对象才允许回收。
- 2 GiB 内存足以作为单用户候选环境，但不允许用内存拼装全量 ZIP、一次读取 50 MB 附件的
  多个副本，或在服务端同时执行高内存 PDF 渲染和导出。必须通过峰值内存实测再冻结实现。
- 文档“数 MB”会显著放大 Markdown 解析、预览、差异比较和搜索成本。后续固定样本至少覆盖
  1 MB、5 MB 和 10 MB 单篇正文，并记录输入延迟、预览耗时、内存和冲突比较退化行为。

#### 3.9.3 带宽与导出影响

阿里云官方说明，控制台购买的公网带宽是出方向带宽；当出方向低于 10 Mbit/s 时，入方向
公网带宽上限为 10 Mbit/s。按当前 3 Mbit/s 出方向做不含协议开销的理论下限估算：

- 从服务器下载 50 MB 附件至少约 2 分 13 秒。
- 下载 500 MB 全量导出包至少约 22 分 13 秒；附件本身若已压缩，归档压缩通常不能显著缩短。
- 向服务器上传 50 MB 文件若能达到 10 Mbit/s 入方向上限，理论至少约 40 秒；实际速度还受
  客户端上行、链路拥塞、TLS 和应用处理影响。

因此全量导出不能依赖一次短超时动态响应。候选方案应异步生成一致性导出快照，并通过支持
断点续传或固定大小分卷的下载方式交付；2 GiB 内存下必须流式生成。暂存包必须计算哈希、设置
到期清理，并在磁盘空间不足时拒绝开始，而不是生成半包。

#### 3.9.4 全量迁移成功标准草案

- 导出包覆盖活动文档、多个笔记本、标签、附件、回收站和仍在保留期的版本，不只导出正文。
- 导出开始前展示预计大小、剩余磁盘要求和人工保管风险；失败、取消和断线均有明确状态。
- 下载完成后用户可以在界面看到包哈希和导出时间，并能在不连接旧服务器的情况下保存包。
- 全新服务器先部署同版本或受支持的兼容版本，再创建新所有者凭据并导入；不得复制旧会话、
  TLS 私钥或有效分享凭据。导入后全部文档默认为未分享，原分享链接不能继续访问。
- 导入前执行完整校验和容量检查，导入后比较文档、笔记本、标签、附件、回收站和版本数量，
  并抽查所有固定样本哈希；任一不一致不得显示“迁移成功”。
- 发布验收必须至少完成一次接近 500 MB 附件总量、包含 50 MB 单附件和数 MB Markdown 文档的
  “旧服务器导出 → 下载 → 全新服务器导入 → 浏览器验证”完整演练。
- 没有自动异地备份时，项目只能承诺恢复到用户最近一次成功保存的全量导出包；导出后的新
  数据丢失窗口由用户实际导出频率决定，不能宣传为自动备份或零数据丢失。

### 3.10 阶段 2 第二轮：功能与容量边界确认

产品负责人于 2026-08-06 将以下 10 项全部按推荐方案确认。这些是当前有效产品边界，后续
调研和验收不得用未经确认的实现细节替换：

1. **公网 HTTP 离线边界**：页面已经打开时，网络中断后必须继续编辑并保存到浏览器本地；
   关闭页面后再离线打开不作保证。
2. **图片粘贴**：必须支持用户在编辑器中通过 `Ctrl+V` 或系统粘贴动作插入图片，并保留文件
   选择上传入口；不要求提供依赖异步剪贴板 API 的独立“读取剪贴板”按钮。
3. **临时文件期限**：“临时上传”描述使用性质，不代表服务器自动过期删除。继续采用手动
   删除、30 天回收站和主动永久删除。
4. **版本历史**：每篇文档最多保留最近 10 个历史版本，历史版本最长保留 30 天；任一条件
   超过即从最旧的非当前版本开始清理。全实例历史版本物理空间上限为 5 GB，超限时同样从
   最旧非当前版本清理；当前版本不得被版本清理规则删除。
5. **正文与附件容量**：单篇 Markdown 正文最大 10 MB，全部活动正文合计最大 5 GB；单附件
   最大 50 MB，附件物理总量最大 500 MB。以上 `MB`、`GB` 均采用十进制字节定义。
6. **附件类型**：允许上传任意扩展名。PNG、JPEG、GIF、WebP 等经过验证的安全图片可以内联
   预览；HTML、SVG、脚本、可执行文件和其他未列入安全预览清单的附件只允许下载，不得在
   GLMake 页面来源中执行或直接嵌入。
7. **公开分享**：分享链接默认不自动过期，由所有者主动撤销；分享页面必须声明禁止搜索引擎
   收录。正文引用的附件可以按只读规则查看或下载，但不得暴露编辑入口、文档列表或原始
   Markdown 下载入口。
8. **登录会话**：会话最长有效期为 30 天；退出时清除当前服务器会话但保留浏览器本地文档；
   必须提供“退出所有设备”。公网 HTTP 风险不改变使用 GLMake 专用且不复用密码的要求。
9. **全量导出格式**：使用公开、版本化、未加密的 `.glmake.zip`。包内包含清单、Markdown、
   元数据和附件，不包含密码或恢复码哈希、会话、TLS 私钥和有效分享凭据。
10. **开源许可证**：GLMake 采用 Apache-2.0；引入任何上游代码前仍须核对其许可证、版权声明
    和依赖兼容性。

#### 3.11.3 通过门槛

以下门槛是进入需求定义前的阶段 2 门禁，不是最终发布性能承诺：

1. **完整性**：任何成功保存、同步、导出或导入的正文与附件，其字节长度和内容哈希必须一致；
   文档、笔记本、标签、版本和引用数量必须一致。部分成功不得显示为完整成功。
2. **浏览器本地能力**：页面已打开后断网，S0 和未保存编辑必须继续写入本地并在恢复网络后
   可同步；关闭页面后离线重开不作为通过条件。普通文本粘贴、图片粘贴和文件选择上传必须在
   目标浏览器中有可用路径，异步剪贴板不可用不得阻断核心流程。
3. **编辑响应**：1 MB 文档连续输入的按键到可见文本 P95 不高于 50 ms，5 MB 不高于 100 ms，
   10 MB 不高于 200 ms；任何样本不得出现持续 2 秒以上无法输入、浏览器崩溃或内容丢失。
   实时预览允许按文档大小节流，但必须显示明确状态并最终收敛到正确结果。
4. **列表与搜索**：S2 中，热启动后的文档列表首次可操作不超过 3 秒；本地标题搜索 P95 不超过
   500 ms，正文搜索 P95 不超过 2 秒。若冷启动依赖公网读取，必须单独报告网络耗时，不能混入
   本地算法结果。
5. **无变更同步**：检查 1000 篇已同步且无修改文档时，不产生正文、附件或新版本写入；稳定
   网络下 P95 在 10 秒内完成，并明确显示检查时间和结果。
6. **冲突与幂等**：S6 的所有旧修订写入都必须进入冲突，四条已确认处理路径均不得丢失未选
   内容；相同幂等请求重复 100 次只能产生一次业务变化。
7. **附件**：50 MB 合法附件在上传、下载、中断和重试后哈希一致；超限请求在写入正式对象前
   被拒绝且不留下可引用半成品。HTML、SVG、脚本、可执行文件和未知类型必须强制下载，并带
   禁止 MIME 嗅探的响应策略，不得在 GLMake 页面来源执行。
8. **版本与删除**：第 11 个历史版本、超过 30 天和超过 5 GB 水位时，均按“最旧非当前版本”
   清理；当前版本永不因历史清理消失。30 天内回收站可恢复，永久删除后活动入口不可读取。
9. **分享与会话**：分享页面给出禁止搜索引擎收录的页面与响应指令；撤销后原链接不能读取正文
   或附件。迁移后旧分享链接全部无效。“退出所有设备”后所有旧会话访问受保护接口均失败。
10. **资源**：任何单次试验不得触发系统 OOM、应用被杀或不可恢复的数据库锁；服务进程峰值
    常驻内存候选门槛为 1.2 GiB，且必须记录系统剩余内存、I/O 和失败清理结果。若门槛不合理，
    只能用实测证据返回修改，不得测试后悄悄放宽。
11. **迁移**：S8 在干净服务器导入后通过全部数量与哈希核对，搜索索引可重建，旧会话与分享
    凭据不恢复；损坏、路径穿越、缺失文件或容量不足必须在修改正式数据前失败。

#### 3.11.4 新发现的组合容量门禁

已确认的 5 GB 活动正文、5 GB 历史版本和 500 MB 附件仍未覆盖回收站正文、数据库、索引、
日志以及生成 `.glmake.zip` 时的数据与临时包并存。若回收站继续增长，40 GiB 系统盘不能仅凭
各分项上限证明安全。

产品负责人于 2026-08-06 已按推荐方案确认：

- 增加 **12 GB 实例受管数据物理上限**，统计活动正文、回收站、历史版本、去重后附件、数据库
  和搜索索引，不含操作系统与应用程序本身；任一业务入口不得绕过。
- 始终为系统、日志、升级回滚和导出临时包保留至少 **8 GB 实际可用空间**。预计写入或导出会
  低于该水位时，在落盘前拒绝并提示先清理，不允许写到磁盘耗尽。
- `.glmake.zip` 仍为单个 ZIP64 文件；服务器完成一致性归档后提供 HTTP Range 下载，使中断后
  可以续传。若归档所需临时空间不足则拒绝开始，不降级为不可校验的部分导出。
- 按 3 Mbit/s 理论下限，12 GB 下载约需 8 小时 53 分钟，实际更久。该上限是安全边界，不代表
  常见导出大小；界面必须在开始前显示预计大小、空间要求和预计下载时间。

S8 必须同时覆盖小规模迁移和接近组合容量上限的迁移；未在目标磁盘水位下完成上限演练前，
不能宣布目标服务器的上限迁移可行。

## 4. “仿写”的三种不同理解

| 方案 | 含义 | 优点 | 主要代价与风险 |
| --- | --- | --- | --- |
| A. 外观仿写 | 复现双栏编辑器、菜单和主要视觉层级，不实现完整数据能力 | 最快验证界面与操作方向 | 容易成为只能看的原型，不能解决真实写作需求 |
| B. 私人功能替代 | 面向个人使用，重做核心编辑、本地保存、文档管理和必要导出；云同步另行决定 | 能形成真正可用的最小产品，范围可控 | 需要先定义数据安全、备份和迁移规则 |
| C. 完整功能等价 | 以自有后端覆盖 Markdown 工作流、多笔记本、附件、同步、分享、冲突和全部非收费能力 | 最接近目标站完整体验且完全自主管理数据 | 自有数据存储、安全、备份和运维责任最高，周期显著更长 |

产品负责人于 2026-08-05 明确选择方案 C：完整替代马克飞象的核心体验，实现除收费
以外的全部功能。项目可以按垂直里程碑逐步交付和验证，但在所有已确认非收费功能完成前，
不得把整个项目称为“完整替代已完成”。

## 5. 候选立项说明

### 5.1 背景

现有马克飞象存在付费同步限制，用户也无法基于公开的官方产品源码自由检查、修改和
长期维护所需能力。项目希望建立一个免费开源的 Markdown 写作工具，参考马克飞象当前
网站的双栏编辑体验和文档工作流，并避免核心本地写作能力依赖持续订阅。

### 5.2 已确认总目标

最终产物必须完整替代调研基线中的马克飞象核心体验，并覆盖除收费以外的全部功能：

- 产品形态仅为 Web 应用，通过浏览器访问。
- 阿里云部署只供产品负责人一人使用，不开放公共注册；公开源码允许其他人自行部署各自
  独立的单用户实例。
- 未登录时可使用本地写作功能，文档只保存在当前浏览器；服务器同步和在线分享必须登录。
- 部署时只建立一个所有者账户，采用用户名、密码和一次性恢复码，不依赖邮箱或第三方登录。
- 服务器持久化保存同步文档的 Markdown 正文、附件、笔记本、标签、必要搜索索引和有限
  版本历史；浏览器同时保留本地工作副本。
- 正式实例允许直接通过公网 HTTP 登录、同步、传输附件和访问分享链接，不要求域名或 HTTPS。
  数据库、附件、全量导出包、登录凭据和会话在相应路径上都可能被取得，产品负责人明确接受
  该风险；部署文档和首次使用提示必须如实说明，且不得把此部署描述为适合重要或敏感文件。
- 用户可以创建、编辑、搜索、组织、恢复和删除 Markdown 文档。
- 编辑区、实时预览、完整目标 Markdown 方言、快捷键和编辑器设置可用。
- 本地自动保存、页面已打开时断网继续编辑、正常联网重启恢复和多窗口占用提示可用；公网
  HTTP 下关闭页面后离线重开不作保证。
- 多笔记本、标签、附件、服务器同步、冲突处理和重新登录可用；每篇文档归属一个笔记本，
  可以拥有多个标签。
- 同步同时支持用户主动触发的手动同步，以及用户自行开启的定时自动同步。
- 自动同步必须同时满足“文档存在待同步更新”和“达到设定时间条件”，无更新时不得
  仅因定时器触发而产生无效写入。
- 自动同步的默认时间条件继承官网设置：每 10 分钟检查一次。
- 自动同步只在 GLMake 页面打开且联网时运行；浏览器关闭后不执行服务端后台同步，重新
  打开页面、恢复网络或页面回到前台时补做一次到期检查。
- 文档使用 `@(笔记本)[标签A|标签B]` 指定目标笔记本和标签；登录后输入 `(` 显示
  自有服务器中的笔记本列表。
- 首次登录不自动上传全部既有本地文档；先展示待同步列表，由用户明确选择。登录后新建
  文档默认进入云同步，自动同步每轮检查“文档管理”中的全部已同步文档并跳过无更新文档。
- 不识别、导入或继续编辑原马克飞象创建的旧笔记；只同步本软件创建并具有本软件
  来源标识的笔记。
- 同步前后，本软件创建的文档均继续由“文档管理”列表统一展示和管理。
- 冲突时同时保留本地版和云端版，并提供查看差异、使用本地版、使用云端版和另存为两个
  文档四种操作；任何自动流程均不得静默覆盖。
- 已同步文档可以生成可撤销的只读公开链接；纯本地文档只提供 Markdown、HTML、PDF 导出
  和本地预览。第一版不提供指定用户分享或多人协作编辑。
- 分享链接默认不自动过期，由所有者主动撤销；分享页面禁止搜索引擎收录，只开放正文引用
  附件的只读查看或下载，不提供编辑、文档列表或原始 Markdown 下载入口。
- 会话最长有效期为 30 天；退出登录时清除当前服务器会话并保留浏览器本地文档，同时提供
  “退出所有设备”。
- 图片、普通键盘/系统粘贴、本地附件以及服务器附件同步可用；保留文件选择上传入口，不要求
  依赖异步剪贴板 API 的独立读取按钮。
- 允许上传任意扩展名附件；只有安全预览清单中的图片可以内联，其余附件强制下载且不得执行。
- Markdown、HTML、PDF 导出以及预览和分享能力可用。
- 普通删除进入回收站并保留 30 天；用户可以主动永久删除。每篇文档保留最近 10 个且最长
  30 天的历史版本，全实例历史版本上限 5 GB，清理规则不得删除当前版本。
- 必须提供包含数据库所需业务数据和全部附件的未加密全量导出包，并通过在干净服务器上的
  全量导入演练证明可迁移、可恢复；没有自动恢复点时，只承诺恢复到最近一次成功保存的导出包。

- 开源许可采用宽松方向：允许他人修改、分发或部署自己的在线服务，不强制其公开

### 5.5 候选成功指标

- 可以完成“新建文档 → 输入 Markdown → 查看预览 → 自动保存 → 关闭并重新打开 →

- 用户数据可以通过明确方式备份和迁出。
- 建立经产品负责人确认的目标功能矩阵；除收费项和明确批准的非目标外，每项均有
  可重复的验收证据，才能认定达到完整功能替代。
- 使用固定样本完成“本地编辑 → 选择上传 → 自有服务器同步 → 另一浏览器重新读取 →
  再次编辑”的往返流程，正文、笔记本、标签、版本和附件满足约定的保真标准。
- 未登录状态触发同步或分享时才进入登录流程；取消登录后，本地功能和已保存内容仍然可用。
- 首次登录不得无条件批量上传全部本地文档；必须展示待同步列表，由用户明确选择。
- 登录后新建文档默认进入同步；手动同步或符合条件的自动同步不得重复创建服务器文档。
- 未登录使用时刷新页面、关闭并重新打开浏览器后，本地文档仍应存在；清除站点数据后
  不承诺恢复，但必须事先通过清晰文案提示风险并提供导出备份能力。
- 页面已打开后断网必须继续编辑和本地保存；公网 HTTP 下关闭页面后再离线打开不作为验收要求。
- 普通粘贴必须能插入文本和图片，文件选择上传必须可用；不得因异步剪贴板 API 不可用而阻断
  图片上传核心流程。
- 公共注册入口和创建第二个所有者账户的普通接口必须不存在或被禁用。
- 手动同步可由用户明确触发；自动同步只在已开启、检测到更新且达到时间条件时执行。
- 浏览器关闭后不执行后台自动同步；页面重新打开、恢复网络或回到前台时补做到期检查。

## 7. 主要风险

| 风险 | 可能影响 | 当前处理 |
| --- | --- | --- |
| 完整功能范围庞大 | 若一次实现全部能力，风险会集中到最后且难以验收 | 保留完整总目标，但拆成可独立运行和验证的垂直里程碑 |
| 开源发布细节未定 | GitHub 所属账号和版本发布流程不明确 | 已确认仓库从获准开发后的首个提交起公开，仓库名为 `GLMake`，并交付源码、标签、更新说明和部署文档 |
| 部署文档不可复现 | 文档遗漏环境、升级或迁移步骤会导致新服务器无法独立上线 | 以全新服务器执行部署冒烟测试，并把成功复现列为交付门槛 |
| 单服务器运行约束 | 主服务、数据库、附件和搜索集中在一台服务器，故障会导致整个应用不可用 | 技术预研必须给出主服务器内的模块隔离、资源水位、监控、升级和回滚方案；所有者定期把全量导出包保存到服务器之外 |
| 开源后的维护压力 | GitHub Issues、安全修复和依赖升级可能超过个人维护能力 | 已明确无 7×24 或商业支持承诺，由维护者排定优先级并公开说明支持边界 |
| 磁盘或附件容量耗尽 | 单用户误上传大量附件或版本历史无限增长会导致写入失败甚至数据库损坏 | 设置实例级磁盘水位、附件上限、版本保留规则和明确告警，在阶段 2 用固定规模样本验证退化行为 |
| 日志泄露隐私 | 故障日志可能意外记录正文、密码、恢复码、会话令牌或附件元数据 | 日志最小化并脱敏，设置保留周期，加入安全测试和部署检查清单 |
| 所有者凭据丢失 | 密码和恢复码同时丢失后无法登录，强行重置可能破坏安全边界 | 首次建立账户时强制下载或抄录恢复码并验证；明确同时丢失时不承诺恢复 |
| 本地数据可靠性 | 自动保存错误可能造成不可恢复的数据丢失 | 立项后先定义存储、备份、恢复和迁移门槛 |
| 自有后端数据损坏 | 数据库、附件或索引损坏会同时影响同步、搜索和恢复 | 数据与索引分级处理，建立一致性校验、全量导出和干净环境导入演练 |
| 所有者会话或服务器被入侵 | 攻击者可能读取、修改或删除全部云端文档 | 产品负责人接受内容泄露风险；仍通过独立密码、登录限速、会话撤销、最小权限和服务器外导出包降低账户复用与数据破坏影响 |
| 服务器静态数据未加密 | 服务器文件、云盘快照或导出包被未授权取得时，正文和附件可能直接泄露 | 按产品负责人决定接受该风险；使用严格文件权限、最小网络暴露和访问控制，并在隐私说明及导出前明确提示 |
| 公网 HTTP 明文传输 | 路径上的第三方可能截获登录密码、会话、正文和附件，或篡改响应 | 产品负责人接受该风险；必须使用 GLMake 专用且不复用的密码，并在部署文档和首次使用时明确提示 |
| HTTP 非安全上下文 | Service Worker、异步剪贴板等浏览器能力可能不可用，影响离线重开或高级图片粘贴 | 阶段 2 按目标浏览器分别实测；保留普通粘贴和文件选择等候选降级路径，无法满足核心体验时返回需求讨论 |
| 人工导出不及时 | 主服务器故障后，导出完成至故障之间的数据无法从导出包恢复 | 明确只承诺恢复到最近一次成功导出；界面显示导出时间并提醒所有者定期下载，首版不虚假承诺自动恢复点 |
| 导出包体积与带宽 | 接近 500 MB 的导出包在 3 Mbit/s 出网下理论下载时间超过 22 分钟，短超时或中断会导致迁移失败 | 流式或异步生成、低内存打包、完整性校验和可恢复下载必须通过上限样本测试 |
| 未加密导出包泄露 | 任何取得导出包的人都可以读取其中全部正文和附件 | 导出前明确警告，下载后由所有者负责保管；导出包不包含账户凭据、会话或有效分享凭据 |
| 本地浏览器数据被清除 | 未登录或尚未同步的文档可能永久丢失 | 明确风险提示、提供导出备份，不虚假承诺云端恢复 |
| 本地到登录状态切换 | 既有草稿可能丢失、重复或被意外上传 | 首次登录展示待上传列表，未经选择不得上传既有本地草稿 |
| Markdown 与服务器模型往返损失 | 扩展语法、元数据、附件或版本迁移可能无法无损恢复 | 建立固定样本和可逆性测试，失败时保留原始数据 |
| 服务器离线或会话失效 | 同步可能延迟，但本地编辑不能被阻断 | 本地优先、写入队列、可重试登录，并在恢复连接后按幂等规则同步 |
| 自动同步重复或并发触发 | 可能重复创建笔记、覆盖新版本或产生无效服务器写入 | 定义变更检测、幂等、单文档互斥和失败重试规则 |
| 文档身份映射失败 | 可能重复创建服务器文档或把一个本地文档关联到错误远端版本 | 使用稳定文档标识、版本号和幂等写入规则；任何不确定关系默认不覆盖 |
| 旧马克飞象数据被误识别 | 可能破坏用户导入内容或产生错误同步关系 | 明确不提供旧同步格式迁移；普通 Markdown 导入必须创建新的 GLMake 文档身份 |
| 上游版本与许可证 | 错误复用可能带来兼容或授权问题 | 建立独立预研，不能凭页面提示直接采用 |
| 视觉参考被误解为品牌复制 | 可能造成品牌混淆、版权风险或像素级照搬 | 只提取配色、密度、排版和交互原则，使用独立名称、素材和组件实现 |
| GLMake 名称存在冲突 | 可能与既有软件、仓库或商标混淆，影响公开发布 | 正式建仓和上线前检索名称、仓库及适用地区商标；发现冲突则返回立项更名 |
| Markdown 方言 | 旧扩展语法可能与现代渲染器不兼容 | 先形成语法兼容矩阵和固定样本 |
| PDF、图片与附件 | 浏览器权限、字体、路径和离线策略复杂 | 属于完整替代范围，分里程碑实现并分别验收 |
| 多窗口与同步冲突 | 可能覆盖新内容或产生重复版本 | 先定义所有权、锁和冲突恢复规则 |
