## 1. 本轮范围与证据级别

本轮为**桌面预检轮**，在本地 Windows 机器上回答候选数据底座与恢复链路的最小可行性
问题。按立项文档 §3.11.1 的规则：目标阿里云 ECS 的基准结果必须在目标服务器上取得；
本轮缺少目标服务器环境，因此本轮全部结果**只能作为观察和方法学验证，不通过阶段 2
门禁**。服务器轮需要产品负责人提供 ECS 上的执行条件后另行执行。

本轮覆盖的最小试验（逐项执行，互不依赖）：

| 试验 | 假设（可被证伪） | 对应预研点 |
| --- | --- | --- |
| E1 SQLite 数据底座基线 | 候选 schema 在 WAL 模式下可以事务化导入 1000 篇文档，500 次串行单文档修订写入无失败，`integrity_check` 通过 | §3.8.2 |
| E2 FTS5 trigram 中文搜索 | trigram 索引可命中 ≥3 字符的中文/英文/数字/混合查询；索引可从正文完整重建且结果一致；少于 3 字符的查询存在已知限制 | §3.8.2 |
| E3 修订号冲突与幂等 | 携带落后 `base_revision` 的写入 100% 返回冲突且不改变服务器版本；相同幂等请求重复 100 次只产生一次业务变化 | §3.8.3 |
| E4 附件不可变对象管线 | 临时写→哈希校验→fsync→原子改名全程无半成品残留；同内容文件只存一个对象；超限文件在正式对象落盘前被拒绝 | §3.8.2 |
| E5 一致性快照 | 并发写入期间 `VACUUM INTO` 可以完成，快照通过 `integrity_check` 且数据自洽 | §3.8.2/§3.8.4 |
| E6 全量导出/导入往返 | ZIP64 流式导出后导入到干净目录，全部哈希与数量核对一致；路径穿越条目被拒绝；独立工具（Python zipfile）可读取同一归档 | §3.8.4 |

本轮**不覆盖**（留给服务器轮或后续轮次）：S3 全量 5 GB 正文、S4 全量 500 MB 附件、
S5 版本/回收站 30 天与 5 GB 水位、S7 分享与会话、浏览器输入延迟与粘贴、公网 HTTP
非安全上下文能力、Argon2id 参数实测（见 §2.3）。

## 2. 固定候选组件

以下为试验用候选实现，**不是已冻结的产品技术设计**。选择原则：零原生依赖、可在
全新机器上按命令复现。

| 组件 | 固定候选 | 备选与理由 |
| --- | --- | --- |
| 运行时 | Node.js 24（本机 v24.16.0，ESM） | Python 3.14 仅作独立交叉验证工具，不作主候选 |
| 数据库驱动 | 内置 `node:sqlite`（SQLite 3.53.0，已验证 FTS5 trigram 与 VACUUM INTO） | `better-sqlite3` 需要原生编译，无必要证据，暂不引入 |
| 数据库模式 | WAL + `synchronous=NORMAL` | 删除模式为默认 rollback journal 的对照项，本轮不做 |
| 搜索索引 | FTS5 `tokenize='trigram'`，可整体重建 | `unicode61` 对无空格中文不满足要求，见立项 §3.8.2 |
| 密码哈希 | 本轮用 `node:crypto` scrypt 占位（E1 不测登录） | Argon2id 仍是生产候选，参数实测属于服务器轮 |
| ZIP 格式 | 仓库内最小 ZIP64 实现（store、含清单），见 `experiments/tools/zip64.mjs` | 不引入第三方打包库；Python 3.14 `zipfile` 用作独立读方交叉验证 |
| 附件存储 | 主机文件系统内容哈希寻址：`objects/<hash 前 2 位>/<sha256>` | 数据库只存哈希、大小、MIME、原始文件名、引用数 |
| 不引入 | PostgreSQL、MinIO、消息队列、任何 npm/pip 第三方依赖 | 与立项 §3.8.2 一致 |

## 3. 固定样本生成方式

生成器：`experiments/tools/gen-samples.mjs`，输出到 `experiments/work/samples/`。

确定性规则（保证不同候选方案可用同一输入复测）：

- 随机源为 mulberry32，各样本集合使用固定种子：S0=100，S1=101，S2=102，S3=103，S4=104。
- 文本内容取自固定的中文句子池、英文词池和标点组合，生成标题、段落、表格、代码块、
  公式、流程图、时序图和复选框；**不使用单一重复字符冒充解析压力**。
- 精确字节大小（十进制）通过真实文本填充后按 UTF-8 字节截断、再以空格补齐达成。
- 二进制附件用 PRNG 按 1 MB 块生成后重复拼装，内容确定、哈希稳定。
- 生成完成时计算并写入 `manifest.json`（每个样本的路径、字节长度、sha256），
  后续所有试验以该清单为核对基准；超限与损坏样本在清单中单独标记。

| 样本 | 本轮规模（桌面缩放） | 服务器轮全量 |
| --- | --- | --- |
| S0 基础正确性 | 20 篇文档、4 笔记本、20 标签，覆盖空文档/中英/混合标点/超长标题/重复标题/公式/表格/代码/流程图/时序图/复选框 | 同左，不缩放 |
| S1 单篇极限 | 1,000,000 / 5,000,000 / 10,000,000 字节各一篇 | 同左，不缩放 |
| S2 数量极限 | 1000 篇文档、20 笔记本、100 标签，含同标题与同更新时间排序冲突样本 | 同左，不缩放 |
| S3 正文容量 | 缩放：10 篇 5 MB 合法文档 + 1 篇 10,000,001 字节超限样本 + 总量超限判定用例 | 合计接近 5 GB 及超总量拒绝样本 |
| S4 附件边界 | 缩放：1 个 50,000,000 字节文件、同内容重复文件、0 字节文件、.png/.html/.svg/.js/.exe 各一、1 个 50,000,001 字节超限样本 | 合计接近 500 MB |
| S5/S6/S7/S8 | S6 的冲突与幂等由 E3 以最小数据覆盖；S5/S7/S8 的完整场景留给后续轮次 | 按立项 §3.11.2 |

## 4. 运行命令

所有命令在 `D:\马克飞象-私人版` 下执行（Git Bash）：

```bash
# 1. 生成全部固定样本（可重复执行，结果按种子确定）
node experiments/tools/gen-samples.mjs

# 2. 逐项执行试验（每项自带计时、哈希核对与 result.json 输出）
node experiments/trials/e1-sqlite-baseline.mjs
node experiments/trials/e2-fts-trigram.mjs
node experiments/trials/e3-revision-idempotency.mjs
node experiments/trials/e4-attachment-pipeline.mjs
node experiments/trials/e5-snapshot.mjs
node experiments/trials/e6-export-import.mjs

# 3. 一键执行整轮（记录环境信息并保存每项 run.log）
node experiments/trials/run-all.mjs --round 2026-08-06-desktop-r1
```

依赖：仅需 Node.js ≥ 22.5（`node:sqlite`）与 Python ≥ 3.11（仅 E6 交叉验证）。
无任何 npm/pip 安装步骤。

## 7. 本轮成功判据（观察级）

试验脚本本身必须满足（否则脚本作废，而不是门槛放宽）：

1. E1–E6 全部执行成功或明确失败并记录原因；无静默跳过的核对项。
2. 所有成功保存/导出的正文与附件字节长度和 sha256 与 `manifest.json` 一致。
3. E3 中任何旧修订写入必须返回冲突；100 次相同幂等请求只产生一次业务变化。
4. E4 超限样本在正式对象落盘前被拒绝，临时目录无残留。
5. E5 快照通过 `integrity_check`，且快照时点数据自洽。
6. E6 导入后数量与哈希全部核对通过，路径穿越样本被拒绝，Python zipfile 交叉读取成功。

性能数字（写入延迟、搜索耗时等）在本轮只记录为本机观察值，不与立项 §3.11.3 的
目标服务器门禁比较。

## 8. 第 1 轮执行结论（2026-08-06-desktop-r1）

试验环境：Windows_NT 10.0.19045 x64，AMD Ryzen 7 3700X（16 线程），32 GB 内存，
Node v24.16.0（SQLite 3.53.0），Python 3.14.5。证据：`experiments/evidence/2026-08-06-desktop-r1/`
（env.json、summary.json、各试验 run.log 与 result.json）。样本确定性已通过两次生成哈希全等验证。

| 试验 | 结果 | 关键观察 |
| --- | --- | --- |
| E1 SQLite 基线 | 假设成立 | 1000 篇事务导入 10.8 ms；500 次串行修订写入 0 失败，P50 0.04 ms、P95 0.099 ms；`integrity_check` 通过；单篇与总量超限拒绝逻辑正确；库文件 839 KB，峰值 RSS 约 46 MB |
| E2 FTS5 trigram | 假设成立，限制被证实 | ≥3 字符查询全部与朴素扫描基准一致（中文 123/123、英文 252/252、数字 1000/1000、混合 1/1），P95 ≤ 0.152 ms；2 字符查询“搜索”返回 0 命中（基准 132），不报错；索引重建结果一致 |
| E3 冲突与幂等 | 假设成立 | 落后 base_revision 写入 100% 返回冲突且不改变服务器版本；草稿完整保留；100 次相同请求仅 1 次业务变化，版本表、修订号、幂等键均无重复 |
| E4 附件管线 | 假设成立 | 哈希与大小全部与 manifest 一致；重复二进制去重，8 输入 → 7 物理对象；50,000,001 B 样本在落盘前被拒绝；临时目录零残留 |
| E5 一致性快照 | 假设成立 | 并发写入（52 次，0 busy 失败）期间 `VACUUM INTO` 耗时 10 ms；快照 `integrity_check` 通过，1000 文档/2000 标签/20 笔记本无孤儿引用 |
| E6 导出/导入往返 | 假设成立 | 101 MB 包（20 文档 + 8 附件 + 清单，29 条目）导入后正文逐字节一致、附件哈希全对；路径穿越攻击包被整包拒绝且零落盘；Python zipfile 交叉读取一致（testzip 无坏条目、条目数与 50 MB 附件哈希一致） |

### 8.1 结论

候选数据底座（SQLite WAL + 哈希寻址附件 + 修订号同步 + ZIP64 全量导出）在桌面规模下
全部假设成立，未发现阻断性缺陷。本轮结果**仅为观察级**：硬件远强于目标服务器
（2 vCPU / 2 GiB / ESSD Entry），样本为桌面缩放，不构成阶段 2 门禁通过。

### 8.2 限制与后续动作

1. trigram 对少于 3 字符的查询静默返回 0 命中（不报错），产品搜索体验必须在需求
   定义阶段给出规则（如提示最少输入 3 字符或降级方案）。
2. `node:sqlite` 不暴露 Online Backup API，本轮以 `VACUUM INTO` 替代验证；若正式方案
   需要增量备份语义，需重评驱动选型。
3. ZIP64 大于 4 GB 单条目的代码路径已实现但未实测；接近 500 MB 附件与 12 GB 受管数据
   上限的迁移演练属服务器轮。
4. 服务器轮（外部阻塞）：需要产品负责人提供目标 ECS 上的执行条件（不需要提供密码或
   密钥进文档，见立项硬约束）；复测项包括写入与搜索性能、峰值内存、磁盘水位、
   Argon2id 参数和公网 HTTP 环境。
5. 浏览器侧门禁（输入延迟、粘贴、断网继续编辑）与分享/会话试验属后续轮次。
